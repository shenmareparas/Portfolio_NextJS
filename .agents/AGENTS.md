# Agent Guidelines & Rules

This document outlines the development guidelines, constraints, and conventions for AI agents working on the **Paras Shenmare Portfolio** codebase.

## Stack & Architecture Constraints

1. **Framework**: Next.js 16 (App Router), React 19, TypeScript, and Bun as the package manager and runner.
2. **Styling**: Tailwind CSS v4. Ensure configuration is done via CSS variables or standard Tailwind classes. Avoid using deprecated Tailwind v3 config structures or styles.
3. **Animations**: Framer Motion. Keep animations smooth, subtle, and responsive.
4. **Haptics**: `web-haptics` (local skill in `.agents/skills/web-haptics`) should be used for interactive elements targeting mobile viewports (e.g., buttons, toggles, form submissions, `/qr` actions). Always use `@/hooks/use-mobile-haptics`, which wraps `useWebHaptics` with `useSyncExternalStore` on `(max-width: 768px)` and forwards optional `WebHapticsOptions` plus the full `(input?: HapticInput, options?: TriggerOptions)` API. Refer to [web-haptics SKILL.md](skills/web-haptics/SKILL.md) for trigger details.
5. **UI Components**: Built using Shadcn UI primitives (`components/ui/`) and Radix UI.
6. **Code Health & Quality Audits**: React Doctor (`^0.9.22`) is installed locally and enforced via pre-commit git hooks and `bun run doctor`. AI agents must follow [react-doctor SKILL.md](skills/react-doctor/SKILL.md) before committing or wrapping up features to maintain a `0`-issue score (plus optional `design` audits).
7. **ui-sdk**: Before using ui-sdk, follow the [ui-sdk SKILL.md](skills/ui-sdk/SKILL.md) if it's installed, and read `node_modules/@ui-sdk/react/docs/llms.txt`. To build a new component, also search `node_modules/@ui-sdk/react/docs/core.md` by heading, and read `rendering.md` next to it.

## Codebase & Folder Conventions

- **Pages and Routing**: All routing is under `app/` using Next.js App Router (`page.tsx` serves Hero, Featured Projects, Expertise, and Testimonials; `/about` serves Bio, Skills, Experience Timeline, Education, and Credentials).
- **Next.js Config (`next.config.ts`)**: Enables `experimental.inlineCss: true` (inlines styles in `<head>` to eliminate render-blocking stylesheet roundtrips), `experimental.optimizePackageImports`, and HTTP security headers (`X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Cross-Origin-Opener-Policy`, `Strict-Transport-Security`, `Permissions-Policy`, `Content-Security-Policy: frame-ancestors 'none'`).
- **Components**:
  - `components/ui/`: Low-level reusable UI components (buttons, inputs, tooltips, dialogs, `command-palette.tsx`, `keyboard-shortcuts-dialog.tsx`, `preloader.tsx`, `marquee.tsx`, `simple-icon.tsx`, `rendered-icon.tsx`, `azure-icon.tsx`, `java-icon.tsx`, `portrait-lock.tsx`, `go-to-top.tsx`, `coverflow-carousel.tsx`, `vertical-gallery.tsx`, `logo-loop.tsx`, `LogoLoop.tsx`).
  - `components/layout/`: Global structure components (SSR-rendered `Header` with Minimalist Spotlight Search Pill `[ Search... ⌘K ]` / `aria-keyshortcuts` and desktop `Primary` + mobile `Mobile` `<nav>` landmarks without `createPortal`, `Footer`, `ClientLayout`).
  - `components/motion/`: Framer-motion helper components (`fade-in.tsx`).
  - Page-specific components reside in folders like `components/home/` (`featured-projects.tsx`, `tech-stack-loop.tsx`, `expertise.tsx`, `testimonials.tsx`), `components/projects/`, `components/experience/`, `components/contact/`, and `components/about/` (`credentials-section.tsx`, `certification-card.tsx`, `achievement-card.tsx`).
- **Hooks**:
  - `hooks/use-card-grid-nav.ts`: Reusable card grid navigation hook synchronizing hover & keyboard focus, suppressing stationary synthetic mousemove events, and coordinating grid spotlight dimming.
  - `hooks/use-draggable-marquee.ts`: Interactive pointer drag, momentum gliding, and horizontal wheel/trackpad scrubbing engine for marquee showcases with click suppression, keyboard focus pausing, offscreen deferral, and reduced motion handling.
  - `hooks/use-is-windows.ts`: SSR-safe platform detection hooks (`useIsMac`, `useIsMobile`, `useIsWindows`) leveraging `useSyncExternalStore` to adapt shortcut key badges (`⌘K` vs `Ctrl+K`), modal cheat sheets, and form submission hints without hydration mismatch flashes.
  - `hooks/use-mobile-haptics.ts`: SSR-safe `(max-width: 768px)` mobile vibration/haptic feedback wrapper forwarding `WebHapticsOptions`, `HapticInput`, and `TriggerOptions` with stable memoized callbacks.
  - `hooks/use-scroll-lock.ts`: Scroll locking hook for full-screen dialogs and modals.
- **Data-Driven Configuration**:
  - **CRITICAL**: Do NOT hardcode personal details, experience, education, or project lists directly in the page components. Always read from or modify files in the `data/` directory:
    - [config.ts](../data/config.ts): Site SEO and metadata.
    - [profile.ts](../data/profile.ts): Bio, contact details, and resume links.
    - [projects.ts](../data/projects.ts): List of featured and personal projects. Key conventions:
      - Featured projects: Designated via `featured?: boolean` in [types/project.ts](../types/project.ts) and ordered in [projects.ts](../data/projects.ts). The top 3 flagship projects showcased on the homepage (`app/page.tsx`) are _Play Store AI Console_, _Chess Offline: Play 2 Player_, and _Live Wallpaper Engine for macOS_.
      - Cover banners: Standardized to `image: "/project/<slug>/banner.webp"`.
      - Gallery layouts: Mobile apps use 3D Coverflow (`galleryLayout: "carousel"`) modeled on the iPhone 18 Pro Max chassis (19.5:9 aspect ratio, micro-thin 1.15mm borders, brushed titanium frame); desktop/macOS/CLI/web console apps (such as _Live Wallpaper Engine for macOS_, _Play Store AI Console_, _NEXU5_) use vertical scrolling (`galleryLayout: "vertical"`).
      - Theme-aware gallery items: Supports `GalleryItem = string | { light: string; dark: string }` for automatic theme-switched screenshots.
      - Theme-aware accent colors: All 11 projects use `{ light, dark }` `accentColor` shades calibrated to maintain `>= 4.70:1` WCAG AA contrast on pill badges and interactive accents across both light and dark themes while preserving app icon branding.
      - Custom social sharing metadata: Projects support `share?: ProjectShareInfo` (`title`, `description`, `image`) for tailored Open Graph and Twitter cards.
      - Screenshot cropping: Window/app captures must have excessive OS transparent drop-shadow borders cropped away (preserving only a subtle 14–15px margin around the window frame) to maintain consistent aspect ratios across the lightbox.
    - Favicons & App Icons: Managed via Next.js metadata file conventions: [app/favicon.ico](../app/favicon.ico) (32x32), [app/icon.png](../app/icon.png) (512x512), [app/apple-icon.png](../app/apple-icon.png) (180x180), and fallback [public/favicon.ico](../public/favicon.ico).
    - [experience.ts](../data/experience.ts) & [education.ts](../data/education.ts): Timelines.
    - [skills.tsx](../data/skills.tsx): Categorized developer skills using Lucide and `simple-icons/icons` (including Bun and Microsoft Azure). Standalone SVG icons (`AzureIcon`, `JavaIcon`) reside in `components/ui/` to guarantee Fast Refresh and `react-doctor/only-export-components` compliance.
    - [tech-logos.tsx](../data/tech-logos.tsx): Vector logos and tech metadata covering all 32 technologies across Skills & Tools on the About page for the infinite `<LogoLoop />` showcase using `simple-icons/icons`.
    - [socials.tsx](../data/socials.tsx): Social links and brand icons (`simple-icons/icons` + Lucide).
    - [testimonials.ts](../data/testimonials.ts): User/client feedback.
    - [expertise.ts](../data/expertise.ts): Core domain expertise list.
- **Types**: All TypeScript interfaces and types must be placed in `types/` (including `ProjectSummary` and `ProjectShareInfo` in `types/project.ts`). Cross-reference types before declaring new ones.

## Styling & Design Guidelines

- **Theme Support**: The site is light/dark system-aware. Ensure all new components use Tailwind's dark-mode classes (e.g., `dark:bg-zinc-950`).
- **Typography & Colors**:
  - Use high-quality curated color palettes (primarily Zinc/Neutral greys, with vibrant, tailored accent gradients).
  - Light-mode `--muted-foreground` is set to `#636363` (`6.00:1` on `#ffffff`, `5.50:1` on `#f5f5f5`) and dark-mode `--muted-foreground` is `#a3a3a3` (`7.85:1` on `#0a0a0a`). Avoid low-opacity modifiers (e.g., `/80`, `/70`, `opacity-70`) on readable UI labels so all text maintains WCAG AA `>= 4.5:1` contrast.
- **Responsive Design**: Ensure mobile-first designs. Never assume a desktop width.
- **Form Validation**: Pair React Hook Form with `zod/mini` (`zod/v4-mini`) for lean, tree-shakeable contact and input validation.

## Performance & Quality Guidelines (React Doctor Audited)

1. **Avoid Layout Property Animations & Broad Transitions**:
   - Do not animate layout-affecting properties (like `height`, `width`, `top`, `left`, etc.) directly via Framer Motion. Instead use GPU-composited CSS transforms (`scaleX`, `scaleY`) and CSS Grid transitions (`grid-template-rows: 0fr -> 1fr`).
   - Avoid `transition-all`. Always specify targeted transitions (e.g., `transition-colors`, `transition-opacity`, `transition-transform`, or `transition-[border-color,box-shadow,transform]`) to prevent browser layout reflow jank.
2. **Prevent Timer and Event Listener Leaks**: Every `setTimeout`, `setInterval`, or DOM event listener registered inside a `useEffect` must return a corresponding cleanup function (`clearTimeout`, `clearInterval`, or `removeEventListener`) to prevent memory leaks and background state updates on unmounted components.
3. **SSR-Safe Mounting without Flicker**: Do not use `useState` + `useEffect` mount flags just to detect client-side rendering. Use React 19's `useSyncExternalStore` with stable module-level selectors to ensure client-only mount state syncs in a single commit, eliminating hydration flashes.
4. **Stable Callback Dependencies**: When using hooks like `useCallback` or `useMemo`, avoid depending on complex/derived variables when only a primitive is needed. Extract the primitive boolean or string in the render scope (e.g., `isDark`, `themeToSet`) and depend on that to prevent redundant hook recreation.
5. **Interactive Element Accessibility**: Never attach click, keydown, or drag handlers directly as React props on static elements (`div`) or semantic non-interactive elements (`section`, `li`). For custom drag-scrollable containers, register listeners dynamically inside a `useEffect` using `.addEventListener()` to bypass static checker violations while ensuring full control over event teardown.
6. **Zod 4 Schema Standards**: Use top-level format builders (e.g., `z.email()`, `z.uuid()`, `z.iso.date()`) rather than chained methods on `z.string()` (e.g., `z.string().email()`) for forward compatibility.
7. **Immediate Above-the-Fold LCP Delivery**: Never wrap above-the-fold hero content (`h1`, `h2`, hero CTA buttons) inside client animation wrappers initialized with `opacity: 0` (e.g. `<FadeIn>`). The hero elements must render immediately in the initial SSR commit to prevent artificial LCP and FCP delays. Below-the-fold sections may use scroll-triggered animations.
8. **Font Swap Strategy**: Google Fonts configured via `next/font/google` must explicitly specify `display: "swap"` to prevent font-blocking delays.
9. **Consistent Canonical URLs**: Maintain strict canonical formatting across `app/layout.tsx`, individual page routes, and `app/sitemap.ts` to prevent Google Search Console duplicate/mismatch warnings.
10. **Pure State Updaters & Zero Cascading Effect Setters**: State updater functions passed to `setState` must be strictly pure and free of side effects. Never call `setState` synchronously within a `useEffect` body to synchronize state with other state variables; derive state during render or update values together in event handlers.
11. **Component Modularity & Low Control Flow Complexity**: Keep React functions concise and modular. Extract complex inline conditional render sections (e.g., project action links, custom modal controls, navigation blocks) into focused sub-components.
12. **Synthetic Mouse Event Debouncing for Touch Gestures**: Mobile browsers fire delayed synthetic `click` (300ms) and `dblclick` (350–500ms) events after touch gestures. When handling custom touch double-tap or touch tap gestures in `pointerup`, record the interaction timestamp (`lastTouchDoubleTapTimeRef.current = Date.now()`) and guard all synthetic mouse listeners (`onDoubleClick`, `onClick`) with a timestamp diff check (`if (Date.now() - lastTouchDoubleTapTimeRef.current < 700) return;`) to prevent synthetic mouse events from immediately inverting touch-toggled states.
13. **Dynamic GPU Optimization (`willChange`) & Module-Level Static Objects**: Never apply permanent `will-change: transform` or `will-change-transform` to idle DOM elements as it wastes dedicated GPU memory compositor layers. Dynamicize `willChange` to active interaction state (e.g. `willChange: isInteracting ? "transform" : "auto"`). Extract static object declarations (e.g., `const SLOT_STYLE = { width: "calc(100% / 3)" } as const;`) to module scope to prevent re-instantiation across renders.
14. **Coordinated Component State via `useReducer` (`react-doctor/prefer-useReducer`)**: When managing multiple interrelated state variables that transition together (such as lightbox zoom scale, pan position, strip offset, animation flags, and dismiss coordinates), consolidate them into a typed `useReducer` with an atomic action dispatch instead of firing disjoint `useState` setters.
15. **Sub-component & Custom Hook Decomposition (`react-doctor/no-giant-component`)**: Maintain concise component boundaries (< 300 lines). Decouple complex gesture/pointer engines and lifecycle listeners into dedicated custom hooks (e.g. `useLightboxGestures`) and encapsulate multi-slot render strips or control bars into focused sub-components (e.g. `LightboxStrip`, `LightboxControls`).
16. **SSR-Safe Client-Side Media Queries via `useSyncExternalStore`**: Avoid registering window event listeners or state flags in `useEffect` to detect media queries (e.g., mobile viewport width). Use `useSyncExternalStore` with module-level subscription functions (`subscribeMobile`, `getMobileSnapshot`, `getServerSnapshot`) to ensure synchronous, flicker-free hydration without cascading effect re-renders.
17. **Strict Device-Targeted Responsive Overlays**: Full-screen modal orientation locks (such as `PortraitLock`) must be scoped strictly to touch devices (`@media(hover:none) and (pointer:coarse)`) to ensure desktop/laptop browsers resized to smaller window heights are never blocked.
18. **Synthetic Mouse Event Suppression & Hover Debouncing (`useCardGridNav`)**: Browsers dispatch synthetic `mouseenter` and `mousemove` events when an element scrolls under a stationary mouse cursor. To prevent stationary cursors from overriding active keyboard `Tab` traversal or stealing focus highlights on scroll, track pointer coordinates with minimum movement thresholds (`Math.abs(clientX - prevX) > 2 || Math.abs(clientY - prevY) > 2`) and give `focusedIndex` precedence over `hoveredIndex`.
19. **Programmatic Focus Anchoring on `#main-content` for Modals & Route Chords**: When dismissing overlays (such as `<CommandPalette>` or `<KeyboardShortcutsDialog>`) or navigating via global keyboard chords (`g h`, `g p`, `1`–`4`), explicitly blur modal inputs, activate `setGlobalKeyboardNav(true)`, and hand off focus directly to `<main id="main-content" tabIndex={-1}>`. This ensures the subsequent `Tab` keystroke immediately targets the first focusable child in page content (e.g., project card #0) rather than falling back to `document.body` or cycling through top header elements.
20. **Card Grid Spotlight Dimming & Focus Parity**: Interactive card grids must provide visual and kinetic parity between mouse hover and keyboard focus states. When any card receives focus via keyboard (`onFocus`) or hover (`onMouseEnter`), adjacent sibling cards dim subtly (`opacity: 0.7` / `scale-[0.98]`). Never apply CSS brightness reduction filters (such as `filter: brightness(0.8)`) to cards as it produces a muddy grey cast on white backgrounds in light mode. Focus styles (`group-focus-within:`) must match hover animations (`group-hover:`) to ensure complete accessibility compliance.
21. **Dual-Column Balanced Layout & Zero-Reflow Collapsible Overflow**: Content-heavy credential and achievement lists must avoid single-column long vertical stacks. Group complementary categories (e.g., Certifications and Achievements) into a responsive side-by-side grid (`grid grid-cols-1 md:grid-cols-2`) with equalized initial item counts to preserve vertical symmetry. Overflow items must be managed via zero-reflow CSS Grid expanders (`grid-template-rows: 0fr -> 1fr` with `transition-[grid-template-rows,opacity]`) and tactile mobile haptic toggles (`useMobileHaptics`). Maintain aesthetic cohesion by strictly using the site's primary and neutral theme tokens rather than multi-colored ad-hoc accents.
22. **SSR-Safe Platform & Operating System Adaptation (`useIsWindows`, `useIsMac`, `useIsMobile`)**: For platform-specific keyboard shortcuts (`Ctrl+K` vs `⌘K`, `Ctrl+↵` vs `⌘+↵`) and responsive controls, use `useSyncExternalStore` with stable module-level getters. Default SSR snapshots to Windows/PC (the majority user base) with `suppressHydrationWarning` on dynamic shortcut badges to prevent hydration mismatch errors, while gracefully suppressing desktop shortcut hints entirely on mobile viewports.
23. **No SSR `opacity: 0` on Template or Reveal Wrappers**: `app/template.tsx`, `FadeIn`, and `ProjectCard` must gate entrance `opacity: 0` animations on `previousPath !== null` (client-side SPA navigations only) so initial SSR documents render at `opacity: 1` without LCP/Speed Index render delay.
24. **Lazy-Loaded Overlays, `zod/mini`, & Intent-Based Prefetch**: Load `CommandPalette` and `KeyboardShortcutsDialog` lazily via `next/dynamic(..., { ssr: false })` only on interaction. Keep `Preloader` as a pure CSS compositor `scaleX` keyframe animation (no `setInterval`), pass trimmed `ProjectSummary[]` props from Server Components, omit `priority` on below-the-fold homepage cards (and limit `/projects` priority preloads to `index < 2`), use `zod/mini` in forms, and prefetch header nav links on hover/focus (`prefetch={false}` + `router.prefetch`).
25. **Off-Screen Deferral & Accessible Motion Controls**: Apply `.defer-offscreen-section` (`content-visibility: auto; contain-intrinsic-size: auto 560px`) to heavy below-the-fold sections like `Testimonials`, use `motion-safe:scroll-smooth` on smooth-scrolling carousels, reuse identical SVG paths via `<symbol>` + `<use>`, cap `Marquee` at `repeat={2}` with `aria-hidden="true"` and `inert` on the cloned track, support hover pausing (`pauseOnHover={true}`) without intrusive manual toggle buttons, and scope `@media (prefers-reduced-motion: reduce)` rules per animation rather than using global `0.01ms` overrides.
26. **Decorative SVG Semantics, Accessible Labels, & Inert Disclosures**: Set `aria-hidden="true"` and omit `role="img"` on decorative SVGs (`SimpleIconComponent` without `label`, `JavaIcon`, `AzureIcon`, UI arrows), keep visible control text verbatim in accessible names (using `aria-keyshortcuts` + `aria-hidden="true"` on shortcut `<kbd>` badges to avoid `label-content-name-mismatch`), pair `aria-expanded` / `aria-controls` with `inert` on collapsed disclosures (`Expertise`, `CredentialsSection`), use Tailwind v4 canonical gradients (`bg-linear-*`) and `min-h-dvh`, and keep interactive `<input>` font sizes at `>= 16px` (`text-base`) on mobile (`CommandPalette`) to prevent iOS Safari zoom.
27. **Global Anchor Typography & Style Isolation**: Ensure all interactive anchor (`a`) tags have `text-decoration: none` by default site-wide to prevent unstyled browser underlines from creeping into navigation bars, action buttons, certification cards, and achievement badges. Never import third-party CSS bundles (such as `@ui-sdk/core/web.css`) into `globals.css` if they globally pollute the root or base anchor elements with default underlines (`text-decoration: underline`).
28. **LogoLoop Component Architecture & Performance**: The `<LogoLoop />` component (`components/ui/logo-loop.tsx`) must maintain low control-flow complexity by decomposing items into `LogoLoopItem` and extracting pure math/geometry helpers to module scope. Avoid ref mutation during render by syncing memoized configuration inside `useIsomorphicLayoutEffect`. Support `disableLinks` so logos can serve as purely visual badges without opening unwanted URLs or hijacking navigation.
29. **Command Palette Scroll/Hover Synchronization & Modular Decomposition**: The `<CommandPalette />` component (`components/ui/command-palette.tsx`) must maintain modular boundaries (< 300 lines) by extracting sub-components (`CommandPaletteHeader`) and custom hooks (`useCommandPaletteHoverScroll`). When scrolling the command list, avoid stale hover highlights remaining on scrolled tiles by tracking pointer coordinates and performing RAF-throttled `document.elementFromPoint` hit-testing on the scroll container. If an element scrolls out from under the cursor, clear `selectedIndex` to `-1`. Ensure `scrollIntoView` calls are strictly gated to keyboard traversal (`navigationMode === "keyboard"`) so mouse wheel/trackpad scrolling never triggers conflicting programmatic jumps. To comply with `react-doctor/no-autofocus`, avoid JSX `autoFocus` attributes on the search input, instead orchestrating focus programmatically via multi-frame requestAnimationFrame after modal mount.
30. **Interactive Draggable Marquee Architecture & Gesture Engine (`useDraggableMarquee`)**: When making marquee showcases interactive (`draggable`), decouple RAF animation loops, pointer drag tracking, momentum gliding, and trackpad/wheel scrubbing into a dedicated custom hook (`hooks/use-draggable-marquee.ts`) under the 300-line ceiling. To prevent `react-doctor/effect-raf-loop-needs-cancel`, keep `rafId` strictly typed to numeric RAF handles (`let rafId = 0`), update only via `rafId = requestAnimationFrame(...)`, and cancel in effect cleanup. Ensure touch gestures defer to native scrolling on mobile, clamp dragging click events during active movement (`isDraggingRef`), pause on keyboard focus or tab blur, and respect `prefers-reduced-motion`.
